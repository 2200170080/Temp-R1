# 未同步的大文件与重建方法

本仓库通过 `scripts/github-sync/autosync.sh` 每 60 秒把服务器工作区自动提交并推送到 GitHub。
有一部分文件**刻意没有入库**，原因只有两类：GitHub 单文件 100 MiB 硬上限，以及"可以从已有产物重建、重复上传没有意义"。

本文逐项说明它们是什么、为什么不在、以及在新机器上怎么重新得到。

## 1. 一句话说明

| 类别 | 是否在仓库 | 原因 |
|---|---|---|
| 源码、脚本、配置、文档 | ✅ 在 | — |
| SFT 冷启动轨迹 `outputs/*.jsonl` | ✅ 在 | 19 MB，是训练输入，无法从别处得到 |
| 过采样后的 SFT 题目 `data/MultiTQ/oversampled_for_sft*.json` | ✅ 在 | 0.6 MB，直接决定 SFT 数据分布 |
| 构建与冒烟日志 `logs/*.log`、`logs/retrieval.log` | ✅ 在 | 体积小，是"这套流程确实跑通过"的证据 |
| MultiTQ 训练集 `train.json` / `train_MULTITQ.json` | ❌ 不在 | 各 131 MiB，**超过 GitHub 100 MiB 硬限** |
| GRPO 用的 6 个 parquet `data/multitq_search2/` | ❌ 不在 | 499 MB，且可由 `multitq_search.py` 一条命令重建 |
| FAISS 索引 `corpus/kg_index/` | ❌ 不在 | 2.7 GB，可由 `build_index.sh` 重建 |
| 训练产物 `LLaMA-Factory/saves/`、`verl_checkpoints/` | ❌ 不在 | 后续训练会写入 checkpoint，体积不可控 |
| `__pycache__/`、`*.pyc`、`.env` | ❌ 不在 | 运行产物与敏感信息 |

## 2. MultiTQ 训练集（131 MiB × 2）

`data/MultiTQ/train.json` 是官方题目集，`data/MultiTQ/train_MULTITQ.json` 是它的副本（`multitq_search.py` 第 307 行硬编码读这个名字，所以必须存在同名文件）。

```bash
cd ~/Temp-R1
curl -L -o /tmp/multitq.zip "https://ghfast.top/https://github.com/czy1999/MultiTQ/raw/main/data/Dataset.zip"
unzip -o /tmp/multitq.zip -d /tmp/multitq_peek
cp /tmp/multitq_peek/MultiTQ/questions/train.json data/MultiTQ/train.json
cp data/MultiTQ/train.json data/MultiTQ/train_MULTITQ.json

# 校验：386,787 条，首条 quid = 1000000
python -c "import json;d=json.load(open('data/MultiTQ/train.json'));print(len(d), d[0]['quid'])"
```

期望输出 `386787 1000000`。

## 3. GRPO 的 6 个 parquet（499 MB）

由 `data/MultiTQ/` 现生成，前置是 `train_MULTITQ.json` 已就位。

```bash
cd ~/Temp-R1
source ~/miniconda3/etc/profile.d/conda.sh && conda activate tempr1
python scripts/data_process/multitq_search.py --input_dir data/MultiTQ --local_dir data/multitq_search2 --template_type base
ls -lh data/multitq_search2/
```

期望得到 6 个文件与下表一致：

| 文件 | 行数 | 体积 |
|---|---|---|
| `train_all.parquet` | 386,787 | 230 M |
| `train_single.parquet` | 283,482 | 168 M |
| `train_multiple.parquet` | 103,305 | 61 M |
| `test_all.parquet` | 54,584 | 32 M |
| `test_single.parquet` | 38,864 | 23 M |
| `test_multiple.parquet` | 15,720 | 9 M |

`train_single + train_multiple` 必须正好等于 `train_all`，否则说明 `qlabel` 出现了第三种取值、有样本被静默丢弃。

## 4. FAISS 索引（2.7 GB）

```bash
cd ~/Temp-R1
bash search_r1/search/build_index.sh
ls -lh corpus/kg_index/
```

期望 `e5_Flat.index` 与 `emb_e5.memmap` 各约 1.4 GB，索引 `ntotal = 461329`、`dim = 768`。语料是仓库内的 `corpus/full_kg.jsonl`（461,329 行，98.40 MiB）。

验证索引可用：

```bash
ls corpus/kg_index/e5_Flat.index >/dev/null && echo "索引就位"
bash scripts/retrieval/retrieval_launch.sh
curl -s -X POST http://127.0.0.1:8000/retrieve -H 'Content-Type: application/json' \
  -d '{"queries":["Who was the last person to visit China before the University of Stellenbosch?"],"topk":1,"return_scores":true}' | head -c 300
```

索引正确时 top-1 是 `Stellenbosch_University Make_a_visit China`，score 约 0.857。

## 5. 训练产物

`LLaMA-Factory/saves/qwen2.5-1.5b-it/full/` 与 `verl_checkpoints/` 存放 SFT、GRPO 的 checkpoint。
它们体积随训练增长，且是"结果"而不是"环境"，因此不入库。需要交付模型时单独打包上传，或推到 release / 对象存储。

## 6. 检查当前还有哪些没同步

```bash
cd ~/Temp-R1
git status --ignored --porcelain=v1 | awk '$1=="!!"{print $2}' | grep -v '__pycache__' | head -20
```

若这条命令列出了你希望入库的文件，说明 `.gitignore` 需要调整；改完 `git add -f <路径>` 或删掉对应规则即可，同步器下一轮会自动提交。
